# 09｜服务器部署操作手册

本手册从“拿到当前生产源码”开始。当前工作站没有 SSH、镜像仓库和生产源码权限，因此以下命令由服务器管理员在受控构建机执行。

## 0. 部署输入

必须准备：

- 本 Bundle，先验证 `manifest/FILES.sha256`；
- 控制面和 Worker 的当前 Git commit SHA；
- V5 现网镜像 digest 与部署清单备份；
- 可写的新分支和镜像仓库；
- 独立 canary 队列/namespace；
- Secret 名称和内网 CA 的可信指纹；
- 至少一个小型高模冒烟文件，以及 N01–N08 受控金样访问权限。

## 1. 验证交接包

```bash
cd Li3D_AutoRetopo_Server_Deployment_V6
python3 scripts/verify_bundle.py .
sha256sum certs/GPU_CONTROL_LAN_CA.crt
```

CA 预期 SHA-256：

```text
ad4a4dbd95bb789be03451ff0c25b2bc65dfe170428bd675789c2ebba1e6dc2b
```

必须通过独立可信渠道与服务器管理员核对该指纹；不能仅相信本包文字。

## 2. 建立不可变基线

```bash
git -C control-plane status --short
git -C worker status --short
git -C control-plane rev-parse HEAD
git -C worker rev-parse HEAD
docker image inspect li3d/blender-worker:1.2.1 --format '{{json .RepoDigests}}'
```

把输出附到变更单。若源码工作树不干净，先确认现有改动归属，不得重置或覆盖未提交修改。

## 3. 新建 V6 分支并合并代码

建议分支：

```text
feature/retopology-v6-high-only-auto-budget
```

按 `docs/07_服务器与现有客户端改造清单.md` 实现：

1. 控制面 V6 metadata adapter；
2. 独立 `retopology-v6` 队列；
3. 高模只读规范化，保留组件；
4. 完整 Agent 执行路径；
5. Blender 分组件生成与最多两轮根因修正；
6. 独立 QA 和八门禁；
7. 产物 SHA 与原子发布；
8. 取消、超时、重启恢复和日志脱敏。

把本包中的 `config/`、`contracts/`、`prompts/`、`skill/` 复制到 Worker 源码的固定 runtime 资源目录。生产代码只能通过固定路径和 SHA 读取它们。

## 4. 服务器单元与契约测试

至少新增下列自动测试：

- V6 request 不允许 `target_faces`；旧 adapter 会删除该字段并写 warning；
- 高模准备器不 join 全部 mesh、不 Decimate、不生成 `reference_low/current_low`；
- 计划/result JSON 必须过 Schema；
- `publish_allowed=true` 时八门禁全部 true 且源 SHA 不变；
- 任一门禁失败时不能写成功指针；
- 幂等、取消、租约重取和上传 SHA 错误；
- MCP 只回环，`.blend` 自动脚本禁用，路径越界被拒绝。

运行 Worker/控制面原有全量测试，不能只跑新用例。

## 5. 构建实现镜像

先由 Worker 源码构建包含真正 V6 编排逻辑的实现镜像，例如：

```bash
docker build --pull \
  --label org.opencontainers.image.revision="$(git -C worker rev-parse HEAD)" \
  -t registry.internal/li3d/blender-worker:1.3.0-retopo-v6-impl \
  worker
```

扫描漏洞和 Secret，记录实现镜像 digest。不能把旧 `1.2.1` 直接作为下面脚本的 `WORKER_IMPL_IMAGE`。

## 6. 构建锁定运行时资产的最终镜像

```bash
export WORKER_IMPL_IMAGE='registry.internal/li3d/blender-worker:1.3.0-retopo-v6-impl@sha256:<digest>'
export RETOPOLOGY_V6_IMAGE='registry.internal/li3d/blender-worker:1.3.0-retopo-v6-runtime'
./scripts/build_runtime.sh
```

镜像内运行：

```bash
docker run --rm \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=2g \
  -e BLENDER_EXECUTABLE=/opt/blender/blender \
  -e CODEX_BIN=/usr/local/bin/codex \
  -e JOB_ROOT=/jobs \
  -e CODEX_HOME=/var/lib/li3d/codex-runtime \
  -v li3d-preflight-jobs:/jobs \
  -v li3d-preflight-codex:/var/lib/li3d/codex-runtime \
  "$RETOPOLOGY_V6_IMAGE" \
  python3 /opt/li3d/bin/v6_worker_healthcheck.py
```

固定最终 digest 后再 push；生产部署使用 digest，不用可变 tag。

## 7. 配置 Secret 和网络

- 根据 `config/worker.env.example` 生成服务器本地 `worker.env.production`，不要把它放回 Bundle/Git。
- Secret 通过 `/run/secrets/*`、Kubernetes Secret 或既有 Secret Manager 注入。
- 配置 egress allowlist、非 root、read-only rootfs、任务磁盘配额、CPU/内存/PID 和超时。
- 只允许 Worker 连接内部队列/存储/控制面和批准的 Codex 端点。
- 运行 `scripts/preflight.py --require-secrets`，输出不得显示 Secret 值。

## 8. 部署 canary

Docker Compose 环境参考：

```bash
export RETOPOLOGY_V6_IMAGE='registry.internal/li3d/blender-worker@sha256:<digest>'
export WORKER_CONCURRENCY=1
docker compose -f container/compose.canary.example.yml config
docker compose -f container/compose.canary.example.yml up -d
```

Kubernetes 环境参考 `container/k8s.canary.example.yaml`，先部署 1 replica，只消费 `retopology-v6-canary`。

不要让 canary 直接消费正式 V5 队列。

## 9. 健康与冒烟

```bash
export CONTROL_PLANE_BASE_URL='https://10.3.34.11'
export SSL_CERT_FILE="$PWD/certs/GPU_CONTROL_LAN_CA.crt"
./scripts/verify_cluster.sh

python3 scripts/smoke_submit.py /secure/test/small-high.blend \
  --base-url "$CONTROL_PLANE_BASE_URL" \
  --ca "$SSL_CERT_FILE" \
  --output /secure/results/retopo-v6-smoke
```

冒烟必须证明：请求没有目标面数、成功返回唯一正式低模、八门禁全通过、所有下载 SHA 正确。

## 10. 金样和故障注入

按 `docs/05_验收矩阵.md`：

1. 把 `tests/golden/N01-N08_training_scene_V09.blend` 放入受控测试存储，不放进生产 runtime 镜像；
2. 由 3D 质量负责人确认一次高模集合映射并拆分为 8 个只含高模的测试输入；
3. 对 N01–N08 全量执行并检查七视图高/低/叠加/线框；
4. 执行 Codex 超时、Blender 崩溃、Worker 重启、存储中断、磁盘满、错误 CA、取消和恶意输入测试；
5. 形成签字报告。

## 11. 灰度生产

建议权重：`0% -> 5% -> 25% -> 50% -> 100%`。每级至少观察一个业务高峰，重点监控：

- 门禁失败率及失败码分布；
- 轮廓/结构回归；
- Blender/Codex 超时和崩溃；
- 队列延迟、峰值内存、磁盘和孤儿进程；
- 上传 SHA 错误和重复发布；
- 旧客户端 deprecated warning 是否消失。

## 12. 回滚

任一 P0 问题立即按 `docs/06_回滚方案.md` 将 V6 入队权重归零、drain Worker、恢复 V5 路由并保留所有诊断。回滚时不要删除 V6 输入或失败产物。

## 13. 部署完成标准

- 源码 commit、镜像 digest、策略/技能 SHA 已冻结；
- 没有目标面数、bootstrap Decimate 或 planning-only 旧路径；
- 所有 P0 测试和 N01–N08 金样通过；
- 安全、取消、重启、SHA、原子发布和回滚演练通过；
- 3D 质量、服务和运维三方签字；
- 生产监控和告警已接入。
